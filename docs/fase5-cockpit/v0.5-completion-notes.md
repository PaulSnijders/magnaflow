# mf-cockpit v0.5 — completion notes (2026-08-07)

Implements [`ontwerp-v0.5.md`](ontwerp-v0.5.md) in `tools/mf-cockpit/`:
nine independent quality-of-life items from daily dashboard use. One
commit per item (branch `fase5-cockpit-v0.5`); the design doc was
written first (Step 0) and `ontwerp-v0.1.md`'s write-action list updated
with writes #7, #8 and the scratchpad non-git store. Mirrors
[`v0.4-completion-notes.md`](v0.4-completion-notes.md)'s style.

## What shipped

### 1. Pages refresh themselves

One shared `Cockpit.live({project, badge, handlers})` (in `assets/app.js`)
replaces the thin `connectEvents`/`renderLiveBadge` pair and owns all the
robustness in one place: heartbeat watchdog, backoff, polling fallback,
visibility refetch, guarded handlers. Server side, `EventsEndpoints` now
emits a heartbeat every ~15 s (see the deviation below on why it is a
`{"kind":"ping"}` data frame, not an SSE comment). A handler is
`{kind, refetch, guard?, onGuardedSkip?}`; a guarded handler skips its
refetch while `guard()` is true and shows a "changed on disk" notice
instead — wired on the config editor (dirty textarea). Every page migrated
(index/project/command/config/specs/chat/scratchpad); each refetches its
own JSON and re-renders, never `location.reload()`.

### 2. Summary top bar

`Cockpit.summaryBar(project)` injects one compact, muted, sticky row under
the header on the five project-scoped pages: a project switcher, the
running command (id + short title + pulsing dot) or idle + latest, per-
status counts, watcher dot, `run k/n` chip, git branch + dirty, and the
item-1 live marker (the bar hosts it via `Cockpit.live`'s `badge`).
`ProjectSummaryDto` gained `Running` (highest-id running command)
alongside `Latest`; the bar's counts/running/watcher come from the fast
summary endpoint, the run chip and git branch from the existing async
`GET .../run` and `GET .../git` — no git subprocess on the fast path.

### 3. Service URL host rewrite

`Cockpit.displayUrl(url, hostname)` — a pure, display-only rewrite: a
service URL whose host is `localhost`/`127.0.0.1`/`::1`/`0.0.0.0` gets
`window.location.hostname` substituted (scheme/port/path preserved), so a
link opened over Tailscale points at the worker, not the browser's own
machine. Configured value kept as the link `title`; localhost viewing is a
no-op. Applied on the Run card, the top-bar run chip tooltip, and the index
run chip tooltip. Server/config/mf-run untouched.

### 4. Remove project — write #7

`DELETE /api/projects/{name}` unregisters, never deletes.
`MagnaflowYmlAppender.RemoveProjectAsync`/`ComposeRemovedContent` is the
mirror of write #6: a byte-for-byte text edit removing one entry from
`cockpit: projects:` (or a legacy root-level `projects:`), `.bak` first,
reparse-verify the entry is gone AND the others survived, restore + 500 on
failure. Shares the appender's single config-write lock (renamed
`ConfigWriteGate`). `ProjectRegistry.Remove` drops the in-memory entry;
`ProjectWatchersHostedService` became `IProjectWatcherRegistry` (watchers
keyed by name) and disposes exactly that project's `FileSystemWatcher`. SSE
kind `projects`; legacy `mf-cockpit.yml` refused. Guard: 409 while any
command is `running`. A separated danger-zone section on `config.html`
with a confirm dialog that says in those words it only unregisters, and
warns (without blocking) when mf-watch is still alive.

### 5. `aborted` attention only for the last command

`AttentionRules.Build` now counts an `aborted` command only when no lane
command has a higher ordinal id (`0005 < 0005B < 0006`). `questions` and
stale `running` unchanged.

### 6. Latest column

`ProjectSummaryDto.Latest` (highest-id command's id/title/status),
computed from the already-scanned lane; rendered as a new "Latest" column
on `index.html`.

### 7. Git pull — write #8

A Pull button on `project.html`'s Git card runs exactly `git pull
--ff-only` via `IGitClient.PullFastForwardAsync` (60 s timeout). `POST
/api/projects/{name}/git/pull` guards first (409 while a command runs via
the shared `ProjectResolver.HasRunningCommand`; 409 on a dirty tree,
message pointing at "Commit all"), then passes git's exit code + merged
stdout/stderr back for inline rendering. `GIT_TERMINAL_PROMPT=0` is set
process-wide at startup so a credentials prompt fails fast.

### 8. Scratchpad — the one out-of-git store

`scratchpad.html?p=<name>`: a single-textarea notepad stored in
`scratchpad/<project>.md` next to the loaded `magnaflow.yml` (directory of
the fase-7 resolved `ConfigPath`), filename via write #6's
`DirNameSanitizer` with a hashed fallback for reserved/empty names —
outside every working copy, never in git. `GET` returns
`{content, hash, savedAt}`; `PUT` enforces hash match (409) and a 256 KB
cap (400), no path parameter. Autosave (debounced 1.5 s, on blur, on
`visibilitychange→hidden`, Ctrl+S/Ctrl+Enter), a saved/unsaved/saving
indicator, and a reload-vs-keep-mine choice on 409. Linked from every
project page's nav.

### 9. Ctrl+Enter submits

`Cockpit.submitOnCtrlEnter(el, submit)` fires a primary action on
Ctrl+Enter (Cmd on macOS) from inside a text input, hint in the button
`title`. Swept across: create draft, follow-up draft, chat send, commit-all
message, config save (also Ctrl+S), the Add-project dialog, and the
scratchpad. Native `<dialog>` already closes on Esc, so the Add-project
modal needed no extra handling.

## Deviations / interpretations worth flagging

- **The heartbeat is a `{"kind":"ping"}` data frame, not an SSE `:`
  comment** as the bouwprompt's item 1 wording suggested. `EventSource`
  never surfaces comment lines to JavaScript, so a comment cannot reset the
  client's own dead-connection watchdog — which is the entire point of the
  heartbeat (the socket-looks-open-but-dead case). A real, named-by-`kind`
  ping frame is visible to `onmessage`, is treated as traffic-only (no
  refetch), and also serves the proxy/keepalive purpose a comment would.
- **Git stays non-substitutable (no `git.command` config knob) for the
  pull** — settled with the user (KISS): git is invoked directly, and the
  endpoint's guards + result passthrough are covered through the existing
  `FakeGitClient` seam. The real `git pull --ff-only` invocation (which
  needs a live upstream) is left to live verification, not a fixture remote.
  The two refusal paths the bouwprompt asked for (dirty tree, running
  command) are covered, plus a happy-path and an ff-refusal, all via the
  fake.
- **Scratchpad on defaults targets the directory of the resolved
  `ConfigPath`** even when the file doesn't exist on disk (the next-to-
  binary primary path) — chosen with the user over a user-config-dir
  fallback. Reserved/empty sanitized names get a stable hashed filename so
  no project name can escape the scratchpad directory or hit a Windows
  device name.
- **The item-3 URL rewrite has no C# or JS unit test in the suite** — it is
  a pure frontend one-liner; the design chose to state the rule in
  `ontwerp-v0.5.md`, keep the function trivially inspectable, and verify it
  live + with the ad-hoc Node harness, rather than introduce a JS test
  runner the repo otherwise lacks.
- **The header `#live` span is left in place (empty, invisible) on the five
  bar pages** — the live marker now lives in the summary bar. Removing the
  header span everywhere was more churn than the invisible empty element
  costs; index/chat still use it (they have no bar).
- **The summary bar makes its own async `GET .../run` and `GET .../git`**
  on every page it appears on, so `project.html` issues those calls twice
  (once for its own cards, once for the bar). Both are async and off the
  fast summary path, so this is wasted work but never blocks render; kept
  simple rather than threading shared state between the page and the bar.
- **New-project directories still don't get a live `FileSystemWatcher`
  until restart** (unchanged from v0.4) — write #7's watcher *removal* is
  wired, but write #6's dynamic *add* was out of scope here too.

## Not done / left for later

  design).
- Post-start liveness / real-upstream integration test for `git pull`
  (needs a fixture remote; the guards are what matter and are tested).
- Dynamic `FileSystemWatcher` registration for newly added projects (still
  a restart to pick up a brand-new project's own lane/evidence changes).

  `submitOnCtrlEnter`) — verified live and by ad-hoc Node for now.
