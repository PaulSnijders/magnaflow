## Context

`tools/install/install.ps1` is the Windows machine install/update path:
stop daemons → publish the four tools renamed to their short names → sync
machine config → PATH → shortcuts → restart. A Linux worker machine needs
the equivalent, idiomatic counterpart. The tools themselves are already
cross-platform (config lookup falls back to `~/.config/magnaflow/`,
spawner has a `/bin/sh` branch); what is missing is purely install/runtime
plumbing. Depends on 0004 (cross-platform service commands) for the target
project's wrappers, but this cmd itself does not touch mf-run.

## Task

1. **`tools/install/install.sh`** (bash, `set -euo pipefail`), mirroring
   install.ps1's flow with Linux idioms:
   - stop running daemons first (systemctl --user stop, fall back to pkill
     on exact names) — same reason as Windows: locked binaries + stale
     in-memory config;
   - `dotnet publish -c Release -p:AssemblyName=<short-name>` each tool to
     `$INSTALL_DIR` (default `~/tools/magnaflow/<tool>/`); remove the
     published legacy `mf-cockpit.yml`;
   - symlink the four binaries into `~/.local/bin/` (on PATH on mainstream
     distros; print a warning when it is not);
   - sync the machine config to `~/.config/magnaflow/magnaflow.yml` from a
     `--config <path>` argument (backup a differing existing copy, like the
     ps1 does);
   - install + enable **systemd user units** `mf-cockpit.service` and
     `mf-watch@.service` (templated on project path) generated by the
     script; `Restart=on-failure` for the cockpit, `Restart=no` for
     mf-watch (its exit codes are meaningful); `loginctl enable-linger`
     hint in output for headless machines;
   - restart the units at the end when they were running (update path =
     re-run, same as Windows).
2. **Linux machine-config template**: `tools/install/magnaflow.linux.yml`
   with the same structure as the Windows one but Linux paths (binaries in
   `~/tools/magnaflow/...`), `git_sync: true` under `watch:` and
   `bind: 0.0.0.0` under `cockpit:` (worker-machine posture), commented
   like the Windows source.
3. **README** (`tools/install/README.md`): add the Linux section — one
   command install/update, where things land, how to see daemon logs
   (`journalctl --user -u mf-cockpit`), and the note that mf-run stays the
   owner of the *project's* dev services (systemd/PM2 supervise MagnaFlow's
   own daemons only — never the target project's debug instance, whose
   crashes must stay visible to the worker).
4. **Tests/validation**: shellcheck-clean; a dry-run flag (`--dry-run`)
   that prints actions without executing, so the script can be sanity-run
   in CI/on Windows.

## Constraints

- Constitution: KISS, no new dependencies beyond bash + systemd + dotnet
  SDK. No sudo required anywhere (user-level install only).
- Do not fold Windows and Linux into one script — two small honest scripts
  beat one clever one.
