# Worker Controller v0.2 — completion notes (2026-07-08)

Implements `specs/002-plan-questions-feedback/` (plan.md/tasks.md). Mirrors v0.1's own
post-completion notes in [`workflow-v0.1.md`](workflow-v0.1.md)'s history — see the spec's
`tasks.md` for the task-by-task breakdown.

## What shipped

- Migrated the file model from `.magnaflow/tasks/NNNN-name/task.md` to the mf-spec prompt lane:
  flat `docs/prompts/NNNN-{cmd,pln,qa,rst}-name.md`; `.magnaflow/<NNNN-name>/` is now machine
  runtime evidence only (`claude.log`, `build.log`, `test.log`, `session.yml`).
- `CmdStatus` extended to `draft | ready | running | questions | done | aborted`; `questions` is
  a non-terminal, revisitable status the human clears by hand-editing the qa file and resetting
  status to `ready` — no controller shortcut exists to resume it directly.
- Every run now executes a plan phase first (a separate agent invocation, still on the invoking
  branch since it only touches bookkeeping): self-answered questions are recorded in the pln
  file; genuine open questions pause the run (qa file + `questions` status, no attempt consumed,
  no work branch ever created); nothing open continues straight into implementation, same
  session, same run.
- Cross-run resume is automatic by default (`.magnaflow/<id>/session.yml`), below explicit
  `resume:`/`group` precedence (unchanged from v0.1 FR-013a).
- Every terminal run (`done`/`aborted`) gets a report (`NNNN-rst-*.md`); a paused run never does
  — the pln + qa already carry the context.
- Project conventions (`CLAUDE.md`, then a constitution file — fixed discovery order, no config)
  are prepended to every phase's prompt automatically.
- `ResultWriter` is retired; its three responsibilities split across `SessionEvidence`
  (`.magnaflow/`), the cmd frontmatter (`status`/`attempts`, unchanged location), and the rst file
  (the human-readable summary, now much richer than v0.1's one paragraph).

## Validation

- 108 unit tests (up from v0.1's 77), covering the new file types (`CmdFile`, `PromptScanner`,
  `PlnFile`, `QaFile`, `RstFile`, `SessionEvidence`, `ConventionLoader`) and the extended
  `TaskRunner` plan/pause/resume/report gate, with fakes as in v0.1.
- End-to-end validation against the real compiled binary, real git, and a disposable project,
  using a controllable stub agent (`agent.command` substitution, same FR-019 mechanism v0.1's own
  validation used) instead of a live Claude Code call:
  - A fully-specified command planned, self-answered, created its work branch only after the
    plan gate passed, implemented, and completed `done` in one run — the two-plane commit
    choreography (bookkeeping on `main`, code on the work branch) verified directly via
    `git log --all`.
  - A genuinely ambiguous command paused at `questions` with zero attempts consumed, no qa/rst
    file confusion, and — critically — **no work branch was ever created** for the paused run.
  - Hand-editing the qa file's answer and resetting `status: ready` (then committing, since the
    dirty-tree guard correctly refused the first attempt) let the next run print "resuming this
    command's own recorded session (self-resume)", re-plan by updating the *same* pln file, and
    reach `done` — confirmed via the identical `session_id` across all three agent invocations in
    that command's `claude.log`.
  - `CLAUDE.md` content was confirmed present in both the plan-phase and execution-phase prompts
    via a debug marker, with no `specs:` reference needed.

## Deviations from the plan worth flagging

- `contracts/file-formats.md`'s qa/pln formats assume the *agent* might write directly; the
  actual implementation has the controller deterministically transpose the pln file's "Open
  questions" section into the qa file (constitution V: no AI-specific parsing beyond that). This
  is consistent with the spec's FR-011 wording ("controller MUST append") but is worth noting
  since `research.md`'s R5 phrasing was looser on this exact mechanism.
- `RstFile`/`PlnFile`/`QaFile` all gained defensive `Directory.CreateDirectory` calls (not called
  out as separate tasks) after the first quickstart run surfaced that `docs/prompts/` isn't
  guaranteed to exist yet when a fresh agent writes its very first sibling file.
- The example project (`examples/hello-website/`) and its docs (`README.md`, `EXAMPLES.md`) were
  migrated/rewritten as part of Polish (tasks.md T038/T039) to the new vocabulary and file
  locations; not a deviation, just called out since it touches files outside `src/`.

## Not done / left for later

- `mf-spec/spec-kit` itself (the installable kit) was not updated to reference this feature —
  out of scope; this feature only touches `tools/worker-controller/`.
- No live-agent (real Claude Code) validation was performed in this session; the stub-agent
  validation exercises the full controller/git/filesystem contract but not the real agent's
  actual planning/coding quality.
